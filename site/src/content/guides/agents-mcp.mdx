## Turn on agent connections

Fillet speaks [MCP](https://modelcontextprotocol.io), the protocol AI agents use to work in other apps. It stays off until you turn it on.

<Platforms>
  <Platform name="iPad">
    1. Open the design you want the agent to work in.
    2. Tap <Ui icon="agents-mcp">Agents</Ui>, the sparkle at the right end of the toolbar, and turn on **Allow agent connections**.
  </Platform>
  <Platform name="Mac">
    1. Open the design you want the agent to work in.
    2. Choose **Design › Allow Agent Connections**, or click <Ui icon="agents-mcp">Agents</Ui>, the sparkle in the toolbar, and select the **Allow agent connections** checkbox.
  </Platform>
</Platforms>

## Connect Claude Code

The popover writes the one command Claude Code needs. You only do this once.

<Platforms>
  <Platform name="iPad">
    1. Tap **Copy command**.
    2. On a Mac on the same Wi-Fi, paste it into Terminal and press Return. Universal Clipboard or AirDrop gets it there.
  </Platform>
  <Platform name="Mac">
    1. Click **Copy command**, or choose **Design › Copy Agent Setup Command**.
    2. Paste it into Terminal and press Return.
  </Platform>
</Platforms>

On iPad the command ends in a token, `Authorization: Bearer …`, which tells your iPad the Mac is yours. Keep it to yourself. If the iPad gets a new address, copy the command again.

<details class="ref">
  <summary>Use Claude Desktop or another MCP client</summary>

  Claude Desktop starts its own tools, so it uses a small helper inside Fillet for the Mac. The helper finds the running app by itself.

  1. In the **Agents** popover on the Mac, click **Copy Claude Desktop config**.
  2. In Claude Desktop, choose **Settings › Developer › Edit Config**.
  3. Paste the entry into `claude_desktop_config.json`, inside `mcpServers` if it's already there, then quit and reopen Claude Desktop.

  ```json
  {
    "mcpServers": {
      "fillet": {
        "command": "/Applications/Fillet.app/Contents/Helpers/fillet-mcp",
        "args": ["--connect"]
      }
    }
  }
  ```

  Other clients connect the same way: give them the address from the popover if they speak HTTP, or the helper if they only start commands.
</details>

## Ask for a part

Ask Claude in plain words, with the design open in Fillet:

```text
> In Fillet, make a wall bracket with two M4 screw holes.
```

The agent names the design, then adds one step at a time. A pill over the view names the agent and the step it's on.

## Undo an agent's step

Agent steps go into the same undo history as yours.

1. Tap **Undo** at the top right, or press <Keys combo="⌘Z" />, to take back the agent's last step.
2. Tap **Redo**, or press <Keys combo="⇧⌘Z" />, to put it back.

To change an agent's step, tap it on the [timeline](/guides/timeline/). To remove it, touch and hold it (on the Mac, Control-click it), then choose **Delete**. The agent can undo its own steps, but never one of yours unless it names it.

## Questions and answers

<FAQ>
  <QA q="What can an agent do?">Almost everything you can: sketch, extrude, revolve, fillet, chamfer, shell, [holes](/guides/holes/) with the same screw presets, combine, move, mirror, pattern, parameters, colours, print check and export. It looks at a picture of its work, and can turn your view to show you. A step that fails, such as a fillet too big for its edge, never lands in your design: the agent gets the reason and tries again.</QA>
  <QA q="What are Scale and Loft steps?">Steps only an agent can make. Tap one on the timeline to change it in the inspector, like any other step.</QA>
  <QA q="Can an agent build with Fillet closed?">
    On the Mac, yes. Add the helper inside the app with a file name:

    ```sh
    claude mcp add fillet-headless -- \
      /Applications/Fillet.app/Contents/Helpers/fillet-mcp \
      ~/Designs/bracket.fillet
    ```

    It makes the file if needed and saves after every step. Open it in Fillet when the agent is done.
  </QA>
  <QA q="Does my design leave my device?">Not through Fillet. A Mac only accepts programs on that Mac, and an iPad only devices with the token. The agent itself may send what it reads to its own service.</QA>
  <QA q="The popover says “Can't listen”.">Another app holds the ports. Fillet tries 7878, then 7879 to 7888. Quit the other app, then turn **Allow agent connections** off and on again.</QA>
  <QA q="The agent can't reach my iPad.">Keep Fillet open on the iPad with the design showing, put the Mac on the same Wi-Fi, and copy the command again.</QA>
</FAQ>
